# 2026-10-30 cx-pieces: send replies in pieces

The owner asked: “真人不会换行继续打字，而是分段发”. Ordinary reply lines and
the existing 【下一条】 separator become consecutive messages. Consecutive list
lines and fenced code retain their internal line breaks. Extra pieces join the
fifth with spaces. A selected sticker follows its own piece; the existing photo
and voice path is unchanged. Checks run before shaping, and a later send failure
stops the remaining sends. The window and history retain one reply; group counts
track the messages sent.

表情包被挡，原来字照发，现在整组不发（卡第 6 条）。History is settled for
an actually split reply; an ordinary single reply keeps the previous behavior.

`reply_in_pieces` defaults to true. `MAX_MESSAGES` remains 5 and `PIECES_NOTE`
is the per-turn instruction. The self-decision switch still controls silence and
the other self-decision choices. AstrBot's segmented reply setting is untouched.
No golden files or other features were intentionally changed. Recorded prompts
and replies can change, so golden recordings need to be regenerated externally.

Offline coverage includes `test_split_at_most_five`,
`test_newlines_lists_and_code_blocks`, `test_faces_stay_in_their_piece`,
`test_pieces_without_self_decide_and_switch_off`, and
`test_pieces_stop_after_send_failure`. The suite and mutation checks were not run
because Python is unavailable in the supplied environment.

Follow-up tests: `test_split_reply_is_one_complete_astrbot_history_entry`,
`test_sticker_follows_its_own_piece`, `test_send_check_and_silence_hold_the_entire_reply`,
`test_group_quote_and_at_only_on_first_piece`, and
`test_first_piece_has_no_pause_later_pieces_wait`. The held-sticker test is now
`test_a_label_the_send_check_holds_back_the_whole_reply`.
