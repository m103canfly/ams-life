## Review #176, revision 1

Only `life_loop.py`, `body.py`, `tests/test_life_loop.py` and this note changed
in this revision. The six requested corrections are:

1. Sleep start and end are stored as integer seconds. The current activity uses
   the same start. Body wake comparisons use integer seconds too, including old
   fractional deadlines. Continuous recovery is still applied only once.
2. An upward need crossing sets `crossed_pending`. Cooldown and restart keep it;
   the next model attempt consumes it. A sustained high need creates no new event.
3. Prompt material uses field whitelists. The current activity exposes only
   location, description, clock time and duration. Day rows expose only clock
   time, activity, duration, feeling and preference. IDs, origins, place keys and
   related-user metadata stay out. Remaining long digit sequences are masked.
4. The parser uses `browse._json_object`, accepts integer strings for minutes and
   treats null text fields as empty. Invalid actions, booleans for minutes and
   malformed field types still fail without retry.
5. Anonymization keeps the owner's names while removing other people's names.
   Related users still include every mentioned person, including the owner, so
   deletion keeps working. Post text still goes through `qzone.post`.
6. Sleep choices before 03:00 trigger the previous evening's notebook immediately,
   as evening choices do. The 03:00 fallback does not write that evening again.

Nine regression tests were added. The cooldown/expiry test now also checks that
an earlier crossing is pending during cooldown and consumed by an expiry call.
The existing parser bounds test now covers numeric strings and rejects bad ones.
Every clock, model response and post in these tests is fake. Files stay in TEMP.
No plugin methods, configuration switches or dependencies were added.

The review's two nonblocking observations remain unchanged: enabling life may

## Changes

- `life_loop.py` adds the minute observer, five event sources, one life model
  call per attempt, cooldown, daily cap, budget gates and conditional menus.
  State lives in `states/life.json`. The due table is empty until 1d uses it.
- Choices update her current activity and her day records. Other people's names
  are anonymized before storage; the owner's names stay. Related people remain
  deletable through the existing store.
  Meals and rest update bodily needs. Photos run in tracked background tasks.
  Posts use the latest photo from her own life choices today, if one exists.
- `mixin_selfie.py` keeps the reply tool's twelve-character limit. Life choices
  add `kind` and cleaned descriptions of at most forty characters. Sleep choices
  last for their selected duration. Other existing validity rules remain.
- `body.py` uses selected activities instead of scheduled sleep and meals while
  they remain valid. Sleep recovery is continuous. Waking marks the end without
  recovering the same hours again. Bodily checkpoints cover sleep across restart.
- `mixin_core.py` binds the body's optional life state. `mixin_autonomy.py` starts
  life for Her without requiring a model during initialization. Each tick checks
  the current switch and model. A module observer wraps the existing message
  handler to read structured mentions; silence detection reads window timestamps.
  No plugin class method was added.
- `mixin_browse.py` and `mixin_group_browse.py` consume one-shot choices at their
  background entries. Their old scheduling remains when life is off. The trip
  implementation itself was not changed.
- `mixin_llm.py` writes the notebook at the first evening or pre-03:00 sleep choice, with a
  03:00 fallback and one sitting record per evening. The old notebook time remains
  when life is off. `app.py` also cancels life, life photos, sticker vector and
  relook tasks, and the idle image task.
- `_conf_schema.json` adds `life_loop_enabled`, default false. `common.py`
  registers the `life` function. Its function switch defaults true; the separate
  master switch keeps life inactive by default.
