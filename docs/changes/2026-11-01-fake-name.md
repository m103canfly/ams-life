# 2026-11-01 fake-name: a made-up display name in the tests

Everywhere the tests and the panel samples used a real person's nickname as a chat
participant's display name, it is now the made-up name "阿橙". Nothing else changed.

## Why

A public repository must not carry a real person's name or nickname. The word was test data
only: a sender name, an alias, an addressed name, a search word, a message text, and the
example text of the panel's sample pages. No plugin module used it.

## What changed

- 31 files under `tests/`, `pages/` and `tools/brain/src/page/`: the listed `tests/*_cases.py`,
  `tests/fake_old_data.py`, `tests/golden_script.py`, the `tests/test_*` files this change lists,
  `pages/dashboard/brain/sample.js`, `pages/dashboard/likeness.js`,
  `pages/dashboard/memories.js`, `pages/starmap/sample.js` and
  `tools/brain/src/page/sample.js`.
- `tests/golden/basic.json` and `tests/golden/full.json` were re-recorded, not edited.
- The three `sample.js` copies are again byte-identical; the page is built by copying
  `tools/brain/src/page/sample.js` over the other two.

## Behaviour that stays the same

Only that one word changed; no other character changed and no code logic changed. Every use
keeps its role: the same person in each case, the same aliases, the same search hits, the same
anonymised and held-back text, the same event titles and prompts. A scan of every file in the
folder (all file types, `.git` excepted) finds 0 occurrences of the old word.

## The goldens

`AMS_UPDATE_GOLDEN=1 python -m unittest tests.test_golden` cannot run in this sandbox: it makes
its data directory with `tempfile`, and the sandbox refuses the OS temp directory
(`PermissionError`, WinError 5). So the same command the golden test runs
(`PYTHONHASHSEED=0 python tests/scenario.py <data> <trace> basic|full`) was run with the data
directory inside the folder. Each new golden was compared with the old one with only that word
replaced: **equal, byte for byte** (both files are the same size before and after: basic
267211 bytes, full 323910 bytes; 64 and 79 changed lines). The old word does not occur in the
new goldens. Re-running `AMS_UPDATE_GOLDEN=1` outside gives the same two files.
