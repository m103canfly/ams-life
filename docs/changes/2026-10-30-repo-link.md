# 2026-10-30 repo-link: the repo address to copy, not a new window

Signoff 44 (the owner chose the recommendation).

## What changed

- In the panel's settings (版本更新), "打开 GitHub 仓库" was a link with `target="_blank"`. AstrBot 4.29.3 shows a
  plugin page in a frame sandboxed `allow-scripts allow-forms allow-downloads` (no `allow-popups`), so it did
  nothing there, in a browser or in the console.
- Now the button is "GitHub 仓库地址": it shows the address in a read-only line with "复制".
  - "复制" tries the clipboard first (`navigator.clipboard.writeText`);
  - when the frame does not let it (AstrBot's frame gives no `clipboard-write`), when there is no clipboard, or
    when it does not answer within 1.5 s, the whole line is selected and the page says to press Ctrl+C.
- The Gitee mirror's button (shown only when a mirror is set) works the same way; when the mirror is changed
  the line follows it, and when it is cleared the line goes.
- Nothing opens a window: no `target="_blank"`, no `window.open`.
- The three buttons carry `fb-skip`: they call nothing in the plugin, so the click feedback (feedback.js) does
  not show "好了" / "没成功" next to them for a regular refresh that happens to start right after.
- Tried in the test shell (tests/panel_shell/, AstrBot's sandbox, made-up data) in headless Edge with real
  mouse clicks, light and dark: the clipboard is refused there, the line is selected, the note says Ctrl+C.

## Files

- `pages/dashboard/repo_link.js` (new): the address line and "复制"; loaded in the page and by the tests.
- `pages/dashboard/index.html`: the two buttons, the line, the script; `styles.css` / `app.js` cache keys.
- `pages/dashboard/app.js`: attaches it; the Gitee button keeps its address in `data-repo`.
- `pages/dashboard/styles.css`: the line's look.
- `tests/test_repo_link.py`: no new window on the page; the address is the repo; the clipboard first, else
  selected for Ctrl+C (refused, missing, no answer); the line follows the buttons (Node, stand-ins).
