# 2026-10-30 cx-wishes: her wish list

## Why

The owner wants her to propose the upgrades and functions she would like, as needs emerge in use.
She can propose requests during a reply or while writing her notebook; the owner reviews them in the panel.

## Existing work checked

The owner supplied the investigation: the AstrBot plugin market had no plugin for a character to
propose requests for owner review. TickTick, Feishu and Vikunja tasks synchronize to external
services; self_iterative_core edits code directly; self_evolution has numbered administrator
approval/rejection as a possible pattern. Letta and Generative Agents had no equivalent way for
the character to record requests. No network recheck was performed in this workspace.

## Changes and switch

- `wishes_enabled`, default false, offers `wish` with `set_now`. The plugin records a proposal in
  `wishes.json`, keeps its self origin, source message and speaker, and recognized people; it offers
  no tool to execute a proposal. `_new_wishes_count` is only a count interface.
- Before storing, known and long numeric identifiers are removed, forgotten names are scrubbed,
  and `_check_for_owner` checks memory entries as the owner's private chat. A missing owner or
  failed check holds the proposal back. This check uses the existing local and optional embedding
  checks; like the existing check, it cannot guarantee detection of every paraphrase.
- Person and source-message forgetting removes matching wishes. The owner can set each to 好,
  先放着 or 不要 from the dashboard. The API requires a loopback peer and local host, rejects proxy
  forwarding headers, and the page hides
  sender and message identifiers; it displays 没开 when disabled.
- The notebook sees the wishes, their status and seven days of category counts, and may propose at
  most two wishes per sitting. Both paths use the same owner check and number removal.
- Blocked reads, unavailable tools and failed image recognition increment fixed categories without
  recording text or addresses. 点不了 is reserved: this checkout has no clickable browser action
  or click-failure site to instrument.
- Writes use a same-directory temporary file, flush and replace the store, and clean up on failure.
- `tests/test_group_browse.py` adds the wish mixin to its isolated forget fixture and points its
  wish store at that fixture's temporary directory.
- No work outside the card was intended. The common-piece and name-index library reads no longer
  attach vectors, because those callers only need text and wish checks must not initialize a vector
  database as a side effect.

## Constants

`OPEN_MAX=30`, `DAILY_MAX=5`, `WHAT_MIN=20`, `WHAT_MAX=60`, `WHY_MAX=100`, and
`DUPLICATE_THRESHOLD=0.88`, `BLOCK_DAYS=7`, `NOTEBOOK_WISH_MAX=2`, and `BLOCK_CATEGORIES`
(网址不能读, 点不了, 看不到图, 工具没有). The similarity uses memory_meta's deterministic character-bigram
similarity (intersection over union), not semantic embeddings; differently worded synonyms can pass
as distinct.
