# 2026-10-30 — cx-slang

Group slang learning in the plugin. The default-off `slang_enabled` switch enables a nightly pass beside the digest and group impressions. `slang_image_api_model` defaults to empty; an empty value counts candidates without a model request. The image API adapter reads its endpoint and key from the existing image configuration for each request, and slang requests use the existing vision spending accounting.

- The `slang/` group files hold the learned meanings, owner deletions, and a 14-day hit ledger. Each hit contains only a phrase, local person identifier, message identifier and time; it never stores the original sentence. The phone supplies short, number-stripped examples only while they remain available.
- Candidates require five messages by three people. Known names, common words, numbers, URLs, placeholders, red lines, private material and forgotten people are excluded. Source narrowing and owner deletion withdraw hits and recalculate the threshold. Unused learned phrases fade after 60 days.
- The reply block is limited to matching words from that group. Unknown words can be asked about when addressed, with a group limit of two prompts per day. The panel exposes a list and a delete endpoint with numbered group labels; deleting blocks relearning.
- This borrows the idea of counting repeated group expressions and guessing meanings from context from self-learning. No self-learning code was copied; the implementation uses the existing ams-life phone, privacy and image API paths.

Files: `_conf_schema.json`, `slang.py`, `mixin_slang.py`, `main.py`, `mixin_autonomy.py`, `mixin_discretion.py`, `mixin_pages.py`, `vision.py`, `tests/test_slang.py`, `tests/slang_cases.py`, `tests/test_basics.py`.
