# 2026-11-01 1d web: 小黑盒 in 钥匙, scan to sign her account in

Card 1d, panel half. The Python half (#181) gave three routes; this is the block in the panel's
钥匙 that uses them. Only `pages/dashboard/`, `NOTICE.md` and a new page test; no Python, no new route.

## What changed

- Under the three keys in 钥匙, a block 小黑盒 (`index.html`, `heybox.js`, a few `.hb-*` styles):
  one line with the state and one button.

  | state | says | button |
  | --- | --- | --- |
  | `idle` | 没登录 | 登录 |
  | `waiting` | 等扫码, the code, 用她那个号的小黑盒 App 扫一下（还剩 N 秒） | 取消 (stops only this side's asking) |
  | `logged_in` | 已登录 | 退出登录 (asks first) |
  | `relogin` | 要重新扫码 | 登录 |
  | `captcha` | 小黑盒要人工验证，先停了；退出登录以后可以重新扫码 | 退出登录 (asks first) |
  | `review_required` | 第一次真跑没成功，先停了，等审核看 | 退出登录 (asks first) |
  | `failed` / `expired` | 没拿到二维码 / 二维码过期了 | 再试 |

  A state it does not know says 说不清现在是什么状态, with 登录. Coming back while the plugin still
  waits on a code it no longer has here: 在等扫码，这边的二维码已经收起来了, with 再试.
- The code is drawn on the page as an SVG of squares by `qrcodegen.js`: Nayuki's QR Code generator
  v1.8.0 (MIT), `typescript-javascript/qrcodegen.ts` at commit `720f62b`, turned into plain JavaScript
  by Node's own `module.stripTypeScriptTypes` (types and comments dropped, nothing else changed). Its
  MIT notice is at the top of the file, with where it came from; `NOTICE.md` has an entry. No package.
- `qr_url` goes only into the code drawer. It is not shown as text, not put in any attribute, not
  written to the console, and never sent anywhere (no image, no address, no other site).
- While a code is up, `page/heybox/status` is asked every 3 seconds until the state is not
  `waiting`, or the code's `expire` seconds are up (then 二维码过期了). Going to another view or
  another tab of 设置 stops it, and so does 取消.
- 退出登录 asks first (退出小黑盒登录吗？…); no, and nothing is sent.
- Only `page/heybox/status`, `page/heybox/login`, `page/heybox/logout`, all POST through the bridge
  (with the page's token on our own server). Answers are read through one or two wrappers.
- Where it shows: on our own panel server. Inside AstrBot the routes are not there, so the block
  stays hidden like 钥匙. Without a bridge (a static preview) it shows 钥匙 with an invented code,
  saying 示例（编造）, and a click says 示例里不发.
- `app.js?v=20261101-4`, `styles.css?v=20261101-3`, `heybox.js?v=20261101-1`, `qrcodegen.js?v=1.8.0`.

## How it was checked

- A stand-in for our own panel server on a test port (127.0.0.1), with a made-up token and made-up
  heybox answers (a made-up code address; 已登录 on the third ask). In a headless Edge:
  - 没登录 → 登录 → the code (567 squares) and 还剩 59 秒 → after three asks 已登录, then no more asking;
  - 退出登录 with the page's confirm answering no: nothing sent; yes: `logout` sent, 没登录 · 退出了;
  - 登录 again, then off to 情绪概览: no more asking, 离开了这一页，这边不再等扫码;
  - every heybox POST carried the token; the code address was nowhere in the page or on the console;
    the page asked no other host for anything heybox (the only other host was `api.github.com`, the
    existing 版本 check in `repo_link.js`);
  - the code is dark squares on white in both themes.
- A static preview (the file opened by itself): 示例（编造）, an invented code, 示例里不发.
- The scratch AstrBot stand-in: the block and 钥匙 stay hidden, and nothing asks the bridge about heybox.
- Tests, one file at a time: the new `test_heybox_page` 11 (each state's words and button; the code
  drawn by the local encoder with `qr_url`, and no part of the address in the page or on the console;
  asking stops when signed in, when time is up, on leaving the view or the tab, and on 取消; 退出登录
  only after a yes; no code / captcha / an HTTP error; the static preview and AstrBot; the drawer's
  MIT notice), `test_plugin_pages` 3, `test_panel_api` 20, `test_memory_list_page` 9,
  `test_likeness_page` 8, `test_golden` 2, `test_golden_standalone` 6, `test_basics` 11. All pass.
  With `qr_url` put into the page's text, or onto the console, `test_heybox_page` fails.
