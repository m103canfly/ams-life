# 她的脑子（可视化）

面板里的一页：`pages/brain/`。把她的记忆、事件、认识的人、群和私聊窗口、本子画成一张会动的网，身体的几样画成中间的“核”。还能一轮一轮看她每次回话想起了什么。

- **只读**：页面只用 `bridge.apiGet` 读，没有任何写的路子。删东西回原来的面板。
- **不出本机**：不从网上加载任何东西，也不往外发。
- **内容点开才给**：整张图只带类别、编号、时间。记忆的原话、人名、QQ 号只在主人点开一颗星时才取，QQ 号还要再点一下才显示。

## 画法

星系的画法、镜头和布局用的是 **Galaxy View**（<https://github.com/longwind1984/galaxy-view>，MIT）。它本来是 Obsidian 插件，这里只拿了跟 Obsidian 无关的部分，放在 `tools/brain/src/galaxy/`：

- 黑底星空、星云、浮在空中的星、星团上的彩色云雾、辉光（bloom）；
- 发光的星、细弧线（我们平常不画线，见下）；
- 布局在后台线程（Web Worker）里算，用 d3-force-3d；
- 点一颗星，只亮它周围；
- 手机上自动降画质。

拿了哪些、改了哪些，见那里的 README。唯一改的一处：私下的星画成空心环。

我们自己写的在 `tools/brain/src/brain.js`：
- 把数据喂给它；
- 每个群一种颜色，私聊统一用淡紫、画成空心；人是暖白色；
- 星系中心一圈会呼吸的光，是身体的七样；
- 只在“想起来”时才画线（`lines.js`），线上跑的小光点（Galaxy View 没有，我们照它弧线的弯法补的）；
- 想起的星的金色光晕、被挡下的灰色光晕；
- 星的名字（窗口、身体、想起的、没说的）；
- 原来就有的筛选、搜索、抽屉、每轮回话那一排。

**第二段（10-28）接上了真数据**：从 AstrBot 后台打开时，页面从面板的只读接口取她的数据（`mixin_brain.py` + `brain_graph.py`）。接口不通、或者直接用浏览器打开 `pages/brain/index.html`，就显示编造的示例（`pages/brain/sample.js`），顶上写明“示例数据（编造）”和原因。

## 怎么看

- **整团星是一个球**（主人 10-28 定的）：
  - 星填满一个球。每个群是球里一块同色的区域，私聊的空心星偏在另一侧，外圈一层淡淡的星勾出球的轮廓，身体的核在球心。
  - 做法：在布局里加一股“往球里收”的力（`tools/brain/src/ball.js`），超出半径的往回拉，球里面靠星之间的斥力撑满；私聊那一侧再加一股轻轻往旁边偏的力。不压成扁盘。
  - 球的半径随星数的立方根变大，星多了也差不多一样密。
- **转动、拨动**（`tools/brain/src/globe.js`，替代 Galaxy View 原来的镜头）：
  - 拖着能往任意方向转，过头顶也行；
  - 手一甩就带着惯性转下去，慢慢停下；手机上一根手指拨，两根手指捏合缩放；
  - 不碰它的时候慢慢自己转；一碰就停，松手 4 秒后再慢慢转起来；
  - 镜头要把相关的星框进来时，球跟着转，把它们转到正面。
- 每个群是一团同色的星；私聊里听到的是淡紫的空心星；人是暖白色的星，在他去过的群和私聊之间。
- **平常星之间不连线**（主人 10-28 定的）：
  - 布局照样用联想、出处、跟谁有关、印象把相关的星排在一起，只是线不画出来；
  - 只有“她想起来”的时候才连线：每轮回话时她顺着想过去的那几条，或者主人点开一颗星时它能联想到的那几条；
  - 左边“显示全部连线”是给主人检查用的开关，默认关；
  - 哪些线该画，规则都在 `tools/brain/src/lines.js`，测试会用 Node 跑它。
- 中间那一圈会呼吸的光是身体：想说话、好奇、无聊、想被看见、说多了、压力、心情。数越高越大越亮。心情低时偏蓝，高时偏黄。
- 每次回话：
  - 想起的星按顺序变成金色、亮起来，每走一步连出一条线，一颗光顺着线流过去；
  - 全部亮完停一会儿，线慢慢淡掉，回到只有星的样子；“动起来”开着时，接着播下一轮；
  - 被分寸表挡下的星是灰的，标着“没说”和它的出处，不连线；
  - 选中一轮时，中间的核换成那一刻的身体。
- 点开一颗星：它能联想到的线亮出来，光点往外流一下，镜头把这几颗星一起框进来；关掉抽屉就收起。
  - 记忆之间的联想；
  - 没有联想的人、窗口、事件，就画它自己的线。
- 鼠标、手指：
  - 拖动转球，甩一下带惯性；滚轮或两指捏合缩放；
  - 点一颗星，打开右边的抽屉；
  - 按 R 或“看全图”回到整个球。

调试用的网址参数：
- `?n=3000`：示例的点数；
- `?theme=light`；
- `?win=w:g2`、`?sel=m:0005`、`?turn=1`、`?q=猫`；
- `?settle=1`：先在主线程铺好再画，截图用；
- `?motion=0`；
- `?tier=mobile`；
- `?lines=all`：打开“显示全部连线”；
- `?debug=1`：布局状态写在顶栏的 `data-debug` 里。

## 打包

页面用的是一个打好的文件 `pages/brain/brain.bundle.js`，提交在仓库里。

重新打包：

```
cd tools/brain
npm ci --ignore-scripts
node build.mjs
```

- 只装三个包，版本都钉死：three 0.184.0、d3-force-3d 3.0.6（跟 Galaxy View 锁定的一样）、esbuild 0.25.5；
- 不跑任何安装脚本；`node_modules` 不提交。
- `build.mjs` 会把打进去的每个包的许可证复制到 `pages/brain/licenses/`。

## 数据格式 `ams-life.brain/1`

`page/brain` 返回这一整块，里面没有任何原话、人名或 QQ 号：

```json
{
  "schema": "ams-life.brain/1",
  "sample": false,
  "now": 1793160000,
  "body": {"social": 0.62, "curiosity": 0.71, "boredom": 0.18, "seen": 0.44,
           "talked": 0.35, "stress": 0.22, "valence": 0.3},
  "nodes": [
    {"id": "w:g1", "kind": "window", "sub": "group", "label": "群1", "w": 1.0},
    {"id": "w:p1", "kind": "window", "sub": "private", "label": "私聊1", "w": 0.6},
    {"id": "p:1", "kind": "person", "label": "人1", "w": 0.7},
    {"id": "m:0001", "kind": "memory", "cat": "偏好", "label": "偏好", "where": "w:g1",
     "ts": 1792900000, "w": 0.41, "vis": "public"},
    {"id": "e:0001", "kind": "event", "cat": "被叫到", "label": "被叫到", "where": "w:p1",
     "ts": 1793150000, "w": 0.5, "vis": "private"},
    {"id": "n:1", "kind": "note", "cat": "群里那一页", "label": "本子", "where": null,
     "ts": 1793100000, "w": 0.6, "vis": "public", "self": true}
  ],
  "edges": [
    {"s": "m:0001", "t": "m:0002", "kind": "link", "w": 3, "ts": 1793000000},
    {"s": "m:0001", "t": "w:g1", "kind": "origin"},
    {"s": "m:0001", "t": "p:1", "kind": "about"},
    {"s": "p:1", "t": "w:g1", "kind": "impression", "w": 0.6}
  ],
  "turns": [
    {"id": "t1", "ts": 1793114880, "where": "w:g2",
     "recalled": ["m:004l", "m:00ei"], "held": ["m:000h"],
     "path": [["m:004l", "m:00ei"], ["m:00ei", "m:000h"]],
     "body": {"social": 0.51, "talked": 0.17}}
  ]
}
```

| 字段 | 意思 |
| --- | --- |
| `nodes[].kind` | `window` 群或私聊窗口（`sub`: `group` / `private`），`person` 人，`memory` 记忆，`event` 事件，`note` 本子条目 |
| `label` | 图上显示的短标签：窗口“群1 / 私聊1”，人“人1”，其他是类别。**不放名字、群名、QQ 号** |
| `cat` | 类别（记忆：偏好、经历、约定…；本子：哪一页） |
| `where` | 出处窗口的 id（本子群里那一页可以是 `null`） |
| `vis` | `public` / `private`，按出处的分寸 |
| `w` | 0–1，点的分量（记忆的重要度、窗口的活跃度） |
| `self` | 本子里她写给自己的条目 |
| `edges[].kind` | `link` 联想（`entry["links"]`，`w` 是一起被想起的次数），`origin` 出处，`about` 跟谁有关，`impression` 群友印象（人 ↔ 群） |
| `turns[]` | 每次回话：`recalled` 想起的（按顺序），`held` 被分寸表挡下的，`path` 顺着哪条线想过去，`body` 那一刻的身体（可省）。**只有 id，没有字** |

id 只是这一页用的编号，不能是 QQ 号或群号：接口用一把只在插件里、每次启动新生成的钥匙算一个带钥匙的哈希（HMAC），所以同一个人在插件这次运行里总是同一个号，拿到号也倒推不出 QQ 号或群号。“群1 / 私聊1 / 人1”按第一次见到的时间排。

点开一个点：`page/brain/node?id=…` 返回

```json
{"title": "群1", "text": "记忆原话（只有记忆、事件、本子有）",
 "lines": [["出处", "群1"], ["能在哪说", "公开：哪里都能说，别处不带名字"]], "has_qq": true}
```

`has_qq` 只有人才有：页面显示“显示 QQ 号”按钮，再点一下才单独取 `page/brain/node?id=…&reveal=qq`，只返回 `{"qq": "…"}`。

搜原话：`page/brain/search?q=…` 返回 `{"ids": [...]}`，页面只显示这些点的标签，不显示原话。

### 分批

`page/brain` 一次最多给 2000 颗星、4000 条线（`brain_graph.PART_NODES / PART_EDGES`）。第一批带 `parts`（一共几批）和 `snap`（这一次的编号），页面再取 `page/brain?part=k&snap=…`。同一次的数据在插件里留 30 秒；这中间主人删了东西，后面几批会回 `{"stale": true}`（不是报错：AstrBot 的页面桥遇到报错只传一句话），页面就从头再取一次。

### 真数据从哪来（`mixin_brain.py`）

| 星 | 从哪来 | `cat` |
| --- | --- | --- |
| 记忆 | 记忆库 `memory/library.json`（不带向量） | 听来的 / 她说的 / 私下 / 总结 |
| 事件 | `archives/events.jsonl` | 那件事的心情（开心、平常……），没有就“事件” |
| 本子 | 她的自我描述里的 `notebook` | 她自己那一页 / 群里那一页 / 私下那一页 |
| 窗口 | 上面这些的出处，加上手机窗口（`phone/`）、群友印象里的群 | — |
| 人 | 关系记录（`users/`）、群友印象、上面这些里“跟谁有关”的人、私聊的对方 | — |
| 身体 | 她现在的七样：想说话、好奇、无聊、想被看见、说了多少、压力、心情 | — |

- 每次吐数据前，每一条都过一遍遗忘登记（跟写库时同一个 `_origin_kept`）；人按“现在”和“最后一次见到时”各问一次；印象另外问 `impression_allowed`。**登记读不出来就报错，什么都不给。**
- 读文件只读：手机窗口直接读文件，不像平常那样顺手清掉过期的行；身体只读现在的数，不往前推。读文件在后台线程里做，不挡她回话。

### 每次回话想起了什么（`brain_turns.json`）

- 召回时（`_memory_recall`）记下：按顺序想起的（最像的在前，然后顺着联想带出来的，再然后别处来的）、顺着哪几条线、被分寸表挡下的（别处私下说的、本来够得上被想起）。
- 只存 id、窗口、时间和身体的七个数，**不存一个字**，只留最近 200 轮。
- 写之前跟别的写一样：这条消息的人或消息在登记里就不记；这条消息进来以后有人被删过（删除计数变了）就不记；登记读不出来就不记。
- 主人删一个人：他私聊里的那些轮整轮删，其余轮里他的记忆删掉；删一条记忆：各轮里删掉它。删空了的轮整轮删。
- 恢复备份：照 PR #10 的规矩，备份里的这份文件跟着回来，再把主人删过的删一遍；最后把不在记忆库里的 id 都清掉。

## 点多了怎么不卡

- 画图是 Galaxy View 的“聚合渲染”：
  - 所有星一次画完（一个 Points），所有线一次画完（一个 LineSegments）；
  - 整个画面不到 10 次绘制调用。
  - 它自己说 3000 多个点、2 万多条线能到 60 帧。
- 布局在后台线程算，主线程不卡。
  - 在 AstrBot 的沙盒页面里后台线程要是起不来，2 秒后自动换到主线程算。
- 选中、筛一个群、每轮回话的亮和暗，都只改每颗星的一个“亮度”数，不重建图。
  - 按类别、公开私下、时间筛，会重建一次，再从原来的位置轻轻重排。
- 我们加的光点、光晕、身体的核，加起来一百多个点，三次绘制调用。
- 名字只给窗口、身体、选中的、想起的、没说的，最多几十个。
- 手机上按 Galaxy View 的档位走：不开辉光，最多 1500 颗星（窗口和人都留着，其余按分量取前面的）。
- 本机无头浏览器（软件渲染，没有显卡）实测：
  - 843 颗星的后台布局 300 步就铺好了；
  - 2740 颗星也能正常出图。
  - 帧率要在主人有显卡的电脑上看才准。
- 第二段模拟 AstrBot 的沙盒页面（同样的 sandbox 标志、安全头，AstrBot 自己的页面桥脚本加在页尾），用 1500 条记忆、375 件事、70 个人、25 个窗口的编造数据：
  - 插件这边拼一次图 13 毫秒（不算读文件），分 2 批，第一批约 600 KB；
  - 沙盒里后台线程能起来，300 步铺好，1990 颗星全显示；
  - 故意禁掉后台线程（`worker-src 'none'`），2 秒后换到主线程算，照样出图，只是铺得慢一些。
